Developers

JavaScript components

44 ES modules, no framework and no build step. Core modules load on every page; components load only when their element is on the page and needed.

#component-address-form.js 1.9 KB

: links an address form's country and province. Shopify's country options carry their provinces as JSON (data-provinces); choosing a country fills the province list (or hides the line when the country has none), and the saved country and province are selected on load.

#component-announcement-bar.js 3.7 KB

: rotates announcements with previous/next buttons and optional autoplay.

All slides share one grid cell, so the bar's height never changes (no layout shift). The server renders the first slide active and the rest inert, so it is correct without JS. Autoplay (WCAG 2.2.2): never starts under prefers-reduced-motion, pauses on hover and focus, and has a visible pause/play button whose choice is respected until the page changes.

#component-card-variants.js 2.0 KB

: the glaze tiles under a product card's name choose a variant right on the card. Each tile is a link to its variant (so without JavaScript it simply opens the product with that glaze); here a click previews it instead: the card's photo, price and link turn to that variant, and the tile is marked as chosen. Opening the card then lands on the product with that glaze.

#component-cart.js 15.0 KB

Cart UI shared by the cart drawer and the cart page.

(snippets/cart-contents.liquid) - Quantity changes (debounced per line) and removals go through the Cart API with Section Rendering; every cart UI on the page re-renders in place from the response (theme:cart:updated). - Optimistic: the line shows its pending state at once; on error the quantity rolls back and the error is shown on that line and announced. - Order note (saved as the shopper types), discount codes (apply, remove, and a clear message for codes that don't apply), gift wrap toggle. - Converts the free-shipping threshold for other currencies with Shopify's live exchange rate. - Reports changes through Shopify's standard cart events. (snippets/cart-drawer.liquid) - Opens after an add to cart and from the header cart icon (not on the cart page itself). - Configures Shopify's storefront actions: openCart opens the drawer, and updateCart refreshes the theme's cart UI in place instead of reloading the page.

#component-certificate.js 1.8 KB

: prints only the certificate. The certificate's markup is copied into a hidden frame with the theme's object-tools stylesheet and the shop's fonts, and the frame is printed, so the page around it never reaches the printer (or the PDF).

#component-commission-form.js 0.7 KB

: fills the work order's object reference from the link that led here (?object=No.%200102, from a sold or made-to-order object's "Commission something similar"). Without JavaScript the field is simply empty.

#component-delivery-estimate.js 4.9 KB

: turns the merchant's fulfillment settings into concrete delivery dates. Computed in the browser because Shopify caches page HTML (ADR-008). Dates are calculated in the shop's timezone (UTC offset rendered by Liquid) and formatted in the page language.

#component-dialog.js 2.9 KB

: wraps a native used as a modal or drawer (menu drawer, search, cart drawer).

<theme-dialog> <dialog id="MenuDrawer" data-ref="dialog" aria-labelledby="MenuDrawerTitle">…</dialog> </theme-dialog> <button type="button" data-dialog-open="MenuDrawer" aria-haspopup="dialog">Menu</button> <a href="/search" data-dialog-open="SearchDialog">Search</a> (link fallback works without JS)

Native showModal() provides the top layer, inert background, Escape and focus containment. This component adds: open triggers anywhere on the page, light dismiss on backdrop click, [data-dialog-close] buttons, focus return, and opening when the theme editor selects a block inside. Scroll lock and open/close transitions are pure CSS (component-dialog.css).

#component-facet-bar.js 1.4 KB

: the horizontal filter bar. Each filter is a
that behaves like a dropdown: one open at a time, Escape closes it and returns focus to its toggle, clicking outside closes it. Filtering itself is handled by ; without JavaScript the disclosures still work.

#component-facet-tools.js 2.3 KB

Filter helpers that need JavaScript, kept out of component-facets.js (snippets/facets-filters.liquid):

  • <facet-search>: a search box in a long filter list. It narrows the values shown, opens "Show more" while there's a query and says when nothing matches. It has no name, so it's never submitted.
  • <price-presets>: quick price ranges. A button fills the From and To fields and submits the form, which <facet-filters> turns into an in-place update.

Both are hidden until they run.

#component-facets.js 9.7 KB

: collection and search results (snippets/facets-layout.liquid).

The markup is a GET form plus links, so it works without JavaScript. This adds:

  • Filtering and sorting in place: on change, fetch the section for the new URL (Section Rendering), morph the results (open filters, the open drawer and focus survive), pushState, and announce the new result count. Price inputs wait until the shopper pauses typing.
  • Chips, "clear all" and pagination links update in place too; back/forward re-render.
  • "Load more" (and infinite scroll) appends the next page to the grid.
  • Shopify standard events: shopify:collection:update / shopify:search:update with the parsed filters and sort, plus shopify:search:update when a search results page loads.

#component-film.js 4.2 KB

: the film in the video sections (sections/film-*.liquid). Plays muted and looping while the section is in view and pauses when it leaves; with reduced motion, Animation intensity Off or in the theme editor it waits for the play button. Publishes playback to the stylesheet as data-playing and --film-progress (0 to 1), keeps a timecode ([data-timecode], minutes:seconds:frames) and marks the chapter being played (aria-current on [data-seek]); chapter buttons seek the film.

#component-footer.js 4.8 KB

: menu accordions, the back-to-top button and the wordmark's fit.
  • Menus are native <details> (data-footer-accordion), so they open and close without JavaScript on small screens. On large screens the footer's CSS shows their links even when closed; this keeps them open there too (for browsers without ::details-content) and stops a click on a heading from closing a column. With "Mobile menus: Stacked" they are always open.
  • Back to top shows after one screen of scrolling, its ring filling with the page's scroll progress; it scrolls smoothly (instantly with reduced motion) and moves focus to the main content.
  • The country and language picker (details[data-dismissible]) closes on Escape, returning focus to its button, and on clicks outside it.
  • The wordmark is sized in Liquid from the name's length, which assumes an average letter width; wide fonts (Unbounded, extended grotesques) run past the edge, so it's scaled down to fit.

#component-gift-card.js 1.8 KB

: the issued gift card page. Copies the code (announced), prints the page and draws the QR code with Shopify's qrcode.js (loaded by the template). Without JavaScript the code is still selectable text and the browser can print.

<gift-card data-qr="{{ gift_card.qr_identifier }}" data-copied="Code copied"> <div data-ref="qr"></div> <button data-ref="copy" data-code="…"> <button data-ref="print"> </gift-card>

#component-glaze-matcher.js 2.1 KB

: picking glaze and clay tiles keeps lit the objects that carry any picked material (data-materials, space-separated handles), rings those that carry all of them, and lets the rest fall back, with a count announced politely. Picking nothing shows every object.

#component-header-menu.js 5.8 KB

: enhances the desktop navigation, which is built from
disclosures and works without JavaScript. Adds: - only one panel open at a time - Escape closes the open panel and returns focus to its toggle - clicking outside or tabbing out of the menu closes it - optional hover intent on precise pointers (data-hover), keyboard and click always work - third-level flyouts in dropdowns: one open at a time, opened on hover with a precise pointer

#component-header.js 3.7 KB

: publishes the header height as --header-height (used by dropdowns and drawers) and, for sticky headers, as --scroll-offset so anchors and focused fields are never hidden underneath it (WCAG 2.4.11). With data-sticky="scroll-up" it slides away while scrolling down and returns when scrolling up, but never while a menu inside it is open or focused. With data-transparent (home page hero) it sets data-scrolled once the page scrolls, and CSS turns the transparent header solid. It also makes `details[data-dismissible]` popovers (the localization picker) close on Escape and on clicks outside them, and refreshes the cart count after any cart change that requested the `cart-icon-bubble` section.

#component-kiln-stage.js 13.3 KB

: depth for the home page's opening. On precise pointers, with motion allowed, the pointer's position over the stage is eased into --px and --py (-1 to 1, centre 0); the stylesheet shifts each layer by its own multiple (the beam and side plates most, the headline least), so the vitrine reads in depth. Leaving the stage settles everything back to the centre.

#component-lot-bid.js 1.5 KB

: the sale room's bid sheet. The raise buttons add one, two or five increments to the current bid (never going below the minimum), and when the lot's clock reaches the closing time the sheet swaps its form for the result (data-lot="closed"). The form itself is Shopify's contact form and works without this.

#component-lot-clock.js 2.0 KB

: keeps a sale-room lot's clock running. The server renders the time left when the page was made (data-closes is the closing time in Unix seconds); this ticks it down once a second and, at the closing time, sets data-state="closed" (the stylesheet swaps the caption) and tells any bid form in the same lot to close. Without JavaScript the clock simply shows the time at render.

#component-loupe.js 2.8 KB

: a maker's loupe over the product plates. On devices with a fine pointer that can hover, moving over a photo shows a round lens with the full-resolution detail under the pointer, ringed like a measuring loupe. Each plate names its large image in data-loupe; the lens loads it on first use. Touch, keyboard and screen reader users keep the gallery and its zoom dialog, which show the same detail; the lens is decoration (aria-hidden) and never takes focus.

#component-media-gallery.js 9.3 KB

: product media viewer.
  • The media list is a native scroll-snap carousel; previous/next buttons and thumbnails scroll it, and the counter/thumbnail state follows whatever is in view (swipe, keyboard or buttons).
  • Follows the selected variant (theme:variant:changed) to its featured media.
  • Deferred media: video, external video and 3D model players load only when their poster is activated, then receive focus. Playing media pauses when another slide comes into view.
  • 3D models load Shopify's model viewer UI and AR (shopify-xr) through Shopify.loadFeatures.
  • Zoom opens a full-screen dialog of all images, scrolled to the chosen one.

#component-pickup-availability.js 1.8 KB

: loads local pickup availability for the selected variant (/variants/{id}/?section_id=pickup-availability) and reloads it when the variant changes. Empty when the variant has no pickup locations.

#component-policy-contents.js 3.4 KB

: a list of a store policy's sections, built from the policy's h2 headings.
  • Moves itself under the policy title, inside Shopify's .shopify-policy__container, so the layout can place it beside the text (template-policy.css); stays hidden when the policy has fewer than three sections. A disclosure on small screens, always open on large ones.
  • Gives each heading an id so the links (and shared links) jump to it.
  • Marks the section being read with aria-current as the reader scrolls.
  • Brings the masthead's tab for this policy into view where the tabs scroll sideways (small screens).

#component-predictive-search.js 5.6 KB

: as-you-type suggestions following the ARIA combobox + listbox pattern.

The form is a normal GET /search form, so search works without JavaScript. Suggestions come from the Predictive Search API rendered by sections/predictive-search.liquid (Section Rendering), which keeps all markup and translations in Liquid.

Keyboard: ArrowDown/ArrowUp move through options (aria-activedescendant), Enter opens the active option, Escape collapses the list (a second Escape closes the surrounding dialog).

#component-price-range.js 2.1 KB

: a two-handle price slider that drives the From and To price fields in the same fieldset. Moving a handle writes the field and fires its `input` event, so the facets form filters exactly as if the shopper had typed; typing in a field moves the handle.

#component-product-form.js 5.1 KB

: adds the product form's line to the cart without leaving the page.
  • Sends the form as-is (id, quantity, selling_plan, properties[…]) through the cart client, requesting the cart-icon-bubble section so the header count updates.
  • Busy state on the submit button, errors from Shopify in an alert region, a success message that is also announced (or, when the theme uses a cart drawer, the drawer opens). The sticky bar submits this same form through its form attribute.
  • Reports the add through Shopify's standard cart events (trackCartAdd).
  • Gift card recipient: fields are enabled (and the email required) only while "send as a gift" is checked; adds the shopper's timezone offset and limits "send on" to the next 90 days.

#component-product-info.js 7.7 KB

: keeps a product section in sync with the selected options.

When an option value (or selling plan) changes, it asks Shopify for the section re-rendered with option_values (ADR-012) and morphs it in place: price, availability, buttons, SKU, inventory, quantity rules and sticky bar all come from Liquid. The media gallery and app blocks are left alone. If the chosen value belongs to another product (combined listings), the whole section is replaced and the URL points at the new product.

Then it: updates the URL (?variant=), announces the new state, emits theme:variant:changed and dispatches Shopify's standard shopify:product:select event.

#component-quantity-input.js 2.3 KB

: decrease/increase buttons for a native number input. Respects min, max and step (B2B quantity rules), disables a button at its limit, and fires a bubbling `change` on the input so forms and the cart react the same way as when typing. Re-syncs when the input's min/max/step change (for example after a variant change re-renders the section).

#component-quick-add.js 3.6 KB

: the product card's quick action. - Single-variant products: adds to the cart in place (header count, drawer and standard events follow automatically). - Products with options: opens the preview. - The preview button (data-ref="preview") opens the preview for any product: a centred dialog with the object's record, price, options and buy buttons ({product.url}?section_id=quick-view). The dialog is created on first use and shared by every card on the page.

#component-recommendations.js 4.6 KB

: loads Shopify product recommendations (related or complementary) through the Recommendations API + Section Rendering, when the element comes near the viewport. Stays empty (and hidden by CSS) if there are none.

Complementary lists can add single-variant items directly ([data-quick-add]). The "bundle" layout totals the main product plus ticked items and adds them in one request.

#component-results-view.js 1.6 KB

: the shopper switches results between the Shelf (objects standing at their relative height on a baseline) and the Index (catalogue rows). Both are CSS layouts of the same cards. The choice is stored on , outside the morphed results so filtering keeps it, and in localStorage so it lasts between pages.

#component-share.js 0.9 KB

: native share sheet where supported, otherwise copies the URL to the clipboard and announces it.

#component-sticky-bar.js 2.3 KB

: shows the sticky bar once the main product form has scrolled above the viewport, and hides it again when the form (or the footer) is visible. While hidden it is inert. Publishes its height as --sticky-bar-height so scroll-padding keeps focused content clear of it (WCAG 2.4.11).

#component-true-scale.js 2.0 KB

: shows an object at its real height on screen. Screens differ in pixel density, so a first step matches an on-screen bank card (85.6 mm wide) to a real one; the result (pixels per millimetre) is kept in this browser so the step is skipped next time. The object's height in mm (data-height-mm) times that gives its true height in pixels, set as --mm and --object-height for the stylesheet.

#core-a11y.js 3.4 KB

@module @theme/a11y Accessibility primitives: live-region announcements, focus management and motion preferences. Prefer native <dialog>.showModal() for modal focus containment; use trapFocus only for non-modal surfaces that still need to keep focus inside (rare).

#core-component.js 2.7 KB

@module @theme/component Base class for every theme custom element. Light DOM only (see ADR-003).

Subclasses implement setup(signal) and attach every listener with { signal }. The signal aborts on disconnect, which happens whenever the theme editor re-renders a section, so listeners never leak and never double up.

Refs: descendants with data-ref="name" are exposed as this.refs.name. Use data-ref="name[]" for arrays. Refs inside nested theme components belong to those components.

Refs are collected on connect, which assumes the element's children are already parsed. That holds because component modules are deferred (type="module") and run after parsing, and because fetched markup is inserted as complete subtrees. Call refresh() after morphing markup.

#core-config.js 2.3 KB

@module @theme/config Reads the theme configuration that layout/head-resources renders into <script type="application/json" id="theme-config">. This is the only bridge from Liquid to JS: routes (locale-aware), the shop money format, translated strings and editor state.

#core-events.js 2.9 KB

@module @theme/events Theme-internal events. Components never call each other's methods; they communicate through these DOM CustomEvents. Names use the theme: prefix so they never collide with Shopify's standard storefront events (shopify:*), which are dispatched separately for apps and analytics.

Add a constant and a JSDoc detail typedef here whenever you introduce an event.

#core-fetch.js 10.4 KB

@module @theme/fetch Network helpers: timeouts, abort support, normalised errors, the Section Rendering API, and a Cart AJAX API client that serialises mutations so rapid clicks can't race.

#core-hydrate.js 5.4 KB

Lazy hydration. Loaded on every page (≈1 KB). Imports a component's module only when needed:

<product-recommendations data-hydrate="visible" data-module="{{ 'component-x.js' | asset_url }}">

Strategies:

  • visible: when the element comes within 200px of the viewport
  • idle: when the browser is idle (2s timeout)
  • interaction: on first pointerenter, focusin or touchstart on the element

Until hydrated the element is plain server-rendered HTML, so it must work (or degrade gracefully) without JS. In the theme editor everything hydrates immediately.

#core-motion.js 3.5 KB

Motion helpers (DESIGN-SYSTEM.md 4, ADR-083), imported by core-hydrate.js when the browser is idle, so they never add to the first-load JavaScript.

  • Reveal fallback: browsers without scroll-driven animations get the same reveals through an IntersectionObserver. Content is only hidden once this runs (html.motion-ready), and whatever is already on screen is marked revealed first, so nothing flashes.
  • Product image morph: with Smooth page transitions on, the clicked card's image is named so the cross-document view transition morphs it into the product page gallery.

#core-standard-events.js 1.2 KB

Shopify standard storefront events (https://shopify.dev/docs/api/storefront-events-and-actions). Dispatches shopify:page:view once per page load and registers the <s-view-event> element, which dispatches view events (product, collection, cart) from Liquid-rendered payloads:

<s-view-event view-event-payload="{{ product | standard_event_data: 'view' | escape }}">…</s-view-event>

This is the only module that statically imports @shopify/standard-events. If the CDN module is blocked (for example by a content blocker), only this script fails; the theme keeps working.

#core-utils.js 10.3 KB

@module @theme/utils Small, dependency-free helpers shared by components.
